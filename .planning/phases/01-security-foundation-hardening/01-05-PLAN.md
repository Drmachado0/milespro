<objective>
Replace every existing `auth.uid() = user_id`-only RLS policy on `travel_*` and `vip_*` tables with the canonical trust-kernel pattern: SELECT keeps soft isolation (USING-only, no `has_plan`), INSERT/UPDATE/DELETE add the hard write boundary via `WITH CHECK (auth.uid() = user_id AND public.has_plan(auth.uid(), '<tier>'))`. After this plan, a Free user's authenticated REST POST to any `travel_*` or `vip_*` endpoint is rejected by Postgres with code 42501 (HTTP 403) — closing CRIT-01 (client-only plan gating).

Purpose: This plan is the SECURITY-CRITICAL center of Phase 1. The trust kernel from Plan 04 is dormant code until policies actually call it. Without this plan, Plans 01-04 ship infrastructure that does nothing observable from a user's perspective. This plan is also the most likely to surface unknowns (e.g., the actual list of `vip_*` tables — RESEARCH §A6 flags this as LOW confidence; CONTEXT D-05 says "all `vip_*` tables").

Output: Two migration files (one for `travel_*`, one for `vip_*`) that DROP the legacy policies via a robust DO block (W-5) and CREATE the trust-kernel-wrapped replacements. Local Supabase verifies via `mcp__supabase__get_advisors lints=security` returning no new high-severity findings AND a "zero legacy survivors" assertion.
</objective>

<scratchpad>
**Why this is Wave 3 (after Plan 04, before Plan 06):**
- Plan 04 ships `has_plan()`; Plan 05 calls it from policies; Plan 06 verifies the policies adversarially. Strict serial dependency.

**Why two migration files instead of one:**
- File 1 (`travel_*`) is the bulk of the work — 12 tables × 4 policies = ~48 CREATE POLICY statements
- File 2 (`vip_*`) is smaller (likely 1-3 tables) and may even be a no-op with documentation
- Splitting allows Plan 06 to assert each independently and reduces blast radius if one rewrite has a typo

**Naming convention decision (CONTEXT discretion §4):**
- Adopt snake_case `<table>_<action>` (e.g., `travel_cruises_select`, `travel_cruises_insert`) — grep-able, CI-friendly
- This DROPS the legacy human-readable policy names ("Users can view their own cruises") — that's intentional; the new convention is grep-first, not sentence-first
- W-5 robustness: instead of per-table named DROP statements (which are fragile to typos / forgotten policies / unexpected legacy variants), use a single DO block that enumerates ALL policies on each table family and drops anything NOT matching the new naming convention. Then CREATE the 4 new policies per table.

**Soft vs hard isolation reminder (D-05/D-06):**
- SELECT on travel_* / vip_*: soft (USING only — no has_plan check; downgraded users still see existing rows)
- INSERT/UPDATE/DELETE on travel_* / vip_*: hard write boundary (WITH CHECK adds has_plan)
- managed_accounts: same soft+hard pattern (Plan 04 already deployed it)
- can_access_account semantics on revoked relationships: HARD (different from downgrade) — but those policies live IN can_access_account, not in this plan

```sql
-- ============================================================================
-- Migration 04: Rewrite travel_* RLS with trust kernel (has_plan)
-- Phase: 01-security-foundation-hardening / Plan 05 / Wave 3
-- Requirement: SEC-01, SEC-02
-- Depends on: 20260512120002_create_has_plan_function.sql (calls public.has_plan)
-- ----------------------------------------------------------------------------
-- Forward: For every travel_* table:
--   1. Drop EVERY existing policy whose name doesn't match the new convention
--      <table>_(select|insert|update|delete) — uses a DO block that enumerates
--      pg_policy directly (W-5: robust against typos / forgotten legacy variants /
--      future drift). The legacy "Users can view their own cruises" style policies
--      are caught regardless of exact wording.
--   2. CREATE the trust-kernel-wrapped pattern:
--        SELECT  USING (auth.uid() = user_id)                                                — soft isolation (D-05)
--        INSERT  WITH CHECK (auth.uid() = user_id AND public.has_plan(auth.uid(), 'pro'))   — hard write boundary
--        UPDATE  USING (auth.uid() = user_id)
--                WITH CHECK (auth.uid() = user_id AND public.has_plan(auth.uid(), 'pro'))   — both clauses (HIGH-04 mitigation)
--        DELETE  USING (auth.uid() = user_id AND public.has_plan(auth.uid(), 'pro'))
--
-- Reverse: Recreate the legacy auth.uid() = user_id policies via 20260131123615_*.sql
--          (kept in git history — see commented rollback at bottom of this file).
--
-- Pre-check: SELECT polrelid::regclass, polname FROM pg_policy
--            WHERE polrelid IN (SELECT oid FROM pg_class WHERE relname LIKE 'travel_%' AND relnamespace = 'public'::regnamespace);
--   (committed in PR description before this migration runs — see /tmp/phase1-preflight-travel-tables.txt)
--
-- Naming convention (CONTEXT discretion §4): snake_case <table>_<action>
--   travel_cruises_select / _insert / _update / _delete  (NOT "Users can view their own cruises")
-- ============================================================================

BEGIN;

-- ============================================================================
-- W-5 robust legacy DROP: enumerate every policy on every travel_% table that
-- DOES NOT match the new naming convention, and drop it. This is more robust
-- than per-name DROP IF EXISTS because it catches:
--   - Legacy "Users can view their own X" variants we forgot to enumerate
--   - Custom one-off policies added outside the standard 4
--   - Renamed policies from previous migration attempts
-- ============================================================================
DO $$
DECLARE
  p record;
BEGIN
  FOR p IN
    SELECT polname, polrelid::regclass::text AS tbl
      FROM pg_policy
     WHERE polrelid IN (
       SELECT oid FROM pg_class
        WHERE relname LIKE 'travel_%'
          AND relnamespace = 'public'::regnamespace
     )
       AND polname NOT LIKE 'travel\_%\_select%' ESCAPE '\'
       AND polname NOT LIKE 'travel\_%\_insert%' ESCAPE '\'
       AND polname NOT LIKE 'travel\_%\_update%' ESCAPE '\'
       AND polname NOT LIKE 'travel\_%\_delete%' ESCAPE '\'
  LOOP
    RAISE NOTICE 'Dropping legacy policy % on %', p.polname, p.tbl;
    EXECUTE format('DROP POLICY %I ON %s', p.polname, p.tbl);
  END LOOP;
END $$;

-- ====== travel_clients (parent table — same pattern; FK target for every other travel_*) ====
CREATE POLICY travel_clients_select ON public.travel_clients
  FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY travel_clients_insert ON public.travel_clients
  FOR INSERT WITH CHECK (auth.uid() = user_id AND public.has_plan(auth.uid(), 'pro'));
CREATE POLICY travel_clients_update ON public.travel_clients
  FOR UPDATE USING (auth.uid() = user_id)
            WITH CHECK (auth.uid() = user_id AND public.has_plan(auth.uid(), 'pro'));
CREATE POLICY travel_clients_delete ON public.travel_clients
  FOR DELETE USING (auth.uid() = user_id AND public.has_plan(auth.uid(), 'pro'));

-- ====== travel_cruises ===========================================================
CREATE POLICY travel_cruises_select ON public.travel_cruises
  FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY travel_cruises_insert ON public.travel_cruises
  FOR INSERT WITH CHECK (auth.uid() = user_id AND public.has_plan(auth.uid(), 'pro'));
CREATE POLICY travel_cruises_update ON public.travel_cruises
  FOR UPDATE USING (auth.uid() = user_id)
            WITH CHECK (auth.uid() = user_id AND public.has_plan(auth.uid(), 'pro'));
CREATE POLICY travel_cruises_delete ON public.travel_cruises
  FOR DELETE USING (auth.uid() = user_id AND public.has_plan(auth.uid(), 'pro'));

-- ====== Repeat the SAME 4-CREATE-POLICY block for EACH remaining travel_* table from preflight ====
-- ====== travel_attractions, travel_cars, travel_hotels, travel_insurances,                    ====
-- ====== travel_quotes, travel_receivables, travel_tickets, travel_transfers                   ====
-- (See /tmp/phase1-preflight-travel-tables.txt for the authoritative table list.
--  The W-5 DO block above already dropped all legacy policies regardless of their
--  exact names, so we only need to CREATE the 4 new policies per table.)

-- ... (repeat the 4-CREATE-POLICY pattern for each table) ...

-- ============================================================================
-- Inline self-check: confirm every travel_* table now has exactly 4 trust-kernel policies
-- AND zero legacy survivors (W-5 hardening — the DROP DO block above MUST have worked).
-- ============================================================================
DO $$
DECLARE
  t record;
  policy_count integer;
  legacy_count integer;
BEGIN
  -- Per-table trust-kernel count check
  FOR t IN SELECT relname FROM pg_class
            WHERE relnamespace = 'public'::regnamespace
              AND relkind = 'r'
              AND relname LIKE 'travel_%'
  LOOP
    SELECT COUNT(*) INTO policy_count FROM pg_policy
      WHERE polrelid = ('public.' || t.relname)::regclass
        AND polname LIKE t.relname || '_%';
    IF policy_count <> 4 THEN
      RAISE EXCEPTION 'travel_* RLS rewrite: table % has % trust-kernel policies (expected 4)', t.relname, policy_count;
    END IF;
  END LOOP;

  -- W-5 zero-legacy-survivors check: any policy on a travel_% table whose name
  -- doesn't match the new convention is a survivor — should be impossible after
  -- the DROP DO block, but assert it explicitly.
  SELECT COUNT(*) INTO legacy_count
    FROM pg_policy
   WHERE polrelid IN (
     SELECT oid FROM pg_class
      WHERE relname LIKE 'travel_%'
        AND relnamespace = 'public'::regnamespace
   )
     AND polname NOT LIKE 'travel\_%\_select%' ESCAPE '\'
     AND polname NOT LIKE 'travel\_%\_insert%' ESCAPE '\'
     AND polname NOT LIKE 'travel\_%\_update%' ESCAPE '\'
     AND polname NOT LIKE 'travel\_%\_delete%' ESCAPE '\';
  IF legacy_count <> 0 THEN
    RAISE EXCEPTION 'travel_* RLS rewrite: % legacy policies survived (expected 0). Check the DROP DO block.', legacy_count;
  END IF;

  RAISE NOTICE 'travel_* RLS rewrite self-check passed: 4 trust-kernel policies per table, 0 legacy survivors';
END $$;

COMMIT;

-- ============================================================================

--   -- Legacy bodies are preserved in supabase/migrations/20260131123615_*.sql; copy
--   -- the CREATE POLICY blocks from there.
--   COMMIT;
-- ============================================================================
```

Apply the SAME pattern as Task 1 but with `'vip'` instead of `'pro'` in the WITH CHECK clause AND `vip_` prefix in the W-5 DO block:

```sql
-- ============================================================================
-- Migration 05: Rewrite vip_* RLS with trust kernel (has_plan('vip'))
-- Phase: 01-security-foundation-hardening / Plan 05 / Wave 3
-- Requirement: SEC-01, SEC-02
-- Depends on: 20260512120002_create_has_plan_function.sql
-- ----------------------------------------------------------------------------
-- Forward: For every vip_* table, DROP all legacy policies (via W-5 DO block,
--          regardless of name) and CREATE the trust-kernel pattern wrapping
--          has_plan(auth.uid(), 'vip'). Same soft+hard-write semantics as
--          travel_* (D-05).
--
-- Reverse: Recreate legacy policies — see git history.
-- Pre-check: /tmp/phase1-preflight-vip-tables.txt — list of tables touched
-- ============================================================================

BEGIN;

-- W-5 robust legacy DROP (same pattern as travel_* migration, vip_ prefix):
DO $$
DECLARE
  p record;
BEGIN
  FOR p IN
    SELECT polname, polrelid::regclass::text AS tbl
      FROM pg_policy
     WHERE polrelid IN (
       SELECT oid FROM pg_class
        WHERE relname LIKE 'vip_%'
          AND relnamespace = 'public'::regnamespace
     )
       AND polname NOT LIKE 'vip\_%\_select%' ESCAPE '\'
       AND polname NOT LIKE 'vip\_%\_insert%' ESCAPE '\'
       AND polname NOT LIKE 'vip\_%\_update%' ESCAPE '\'
       AND polname NOT LIKE 'vip\_%\_delete%' ESCAPE '\'
  LOOP
    RAISE NOTICE 'Dropping legacy policy % on %', p.polname, p.tbl;
    EXECUTE format('DROP POLICY %I ON %s', p.polname, p.tbl);
  END LOOP;
END $$;

-- ====== vip_lounge_visits ========================================================
CREATE POLICY vip_lounge_visits_select ON public.vip_lounge_visits
  FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY vip_lounge_visits_insert ON public.vip_lounge_visits
  FOR INSERT WITH CHECK (auth.uid() = user_id AND public.has_plan(auth.uid(), 'vip'));
CREATE POLICY vip_lounge_visits_update ON public.vip_lounge_visits
  FOR UPDATE USING (auth.uid() = user_id)
            WITH CHECK (auth.uid() = user_id AND public.has_plan(auth.uid(), 'vip'));
CREATE POLICY vip_lounge_visits_delete ON public.vip_lounge_visits
  FOR DELETE USING (auth.uid() = user_id AND public.has_plan(auth.uid(), 'vip'));

-- ... repeat for any other vip_* table from preflight ...

-- Inline self-check: every vip_* table has 4 trust-kernel policies AND zero legacy survivors
DO $$
DECLARE
  t record;
  policy_count integer;
  legacy_count integer;
BEGIN
  FOR t IN SELECT relname FROM pg_class
            WHERE relnamespace = 'public'::regnamespace
              AND relkind = 'r'
              AND relname LIKE 'vip_%'
  LOOP
    SELECT COUNT(*) INTO policy_count FROM pg_policy
      WHERE polrelid = ('public.' || t.relname)::regclass
        AND polname LIKE t.relname || '_%';
    IF policy_count <> 4 THEN
      RAISE EXCEPTION 'vip_* RLS rewrite: table % has % trust-kernel policies (expected 4)', t.relname, policy_count;
    END IF;
  END LOOP;

  -- W-5 zero-legacy-survivors check
  SELECT COUNT(*) INTO legacy_count
    FROM pg_policy
   WHERE polrelid IN (
     SELECT oid FROM pg_class
      WHERE relname LIKE 'vip_%'
        AND relnamespace = 'public'::regnamespace
   )
     AND polname NOT LIKE 'vip\_%\_select%' ESCAPE '\'
     AND polname NOT LIKE 'vip\_%\_insert%' ESCAPE '\'
     AND polname NOT LIKE 'vip\_%\_update%' ESCAPE '\'
     AND polname NOT LIKE 'vip\_%\_delete%' ESCAPE '\';
  IF legacy_count <> 0 THEN
    RAISE EXCEPTION 'vip_* RLS rewrite: % legacy policies survived (expected 0)', legacy_count;
  END IF;

  RAISE NOTICE 'vip_* RLS rewrite self-check passed';
END $$;

COMMIT;
```

For EACH `vip_*` table from preflight, append the same 4-CREATE-POLICY block (the W-5 DO block already drops legacy regardless of name).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated client ↔ travel_* / vip_* tables | RLS WITH CHECK clauses now invoke `has_plan()` to enforce server-side plan gating — replacing client-only gating (CRIT-01) |
| Soft-isolation SELECT ↔ Hard-write WITH CHECK | SELECT post-downgrade still works (D-05 product decision: don't surprise downgrading users by hiding their existing data); INSERT/UPDATE/DELETE post-downgrade fail with 42501 (boundary enforced) |
| UPDATE policy USING ↔ WITH CHECK | Both clauses present on every UPDATE — closes the HIGH-04 "RLS that LOOKS secure but isn't" foot-gun (USING gates which rows can be targeted; WITH CHECK gates what they can be mutated to) |
| Legacy policy DROP ↔ trust-kernel CREATE | W-5 DO block enumerates pg_policy directly so legacy variants (typos, forgotten names, custom one-offs) cannot survive the rewrite |
