<objective>
Bootstrap the native iOS and Android Capacitor projects, lock app identity to `br.com.milespro.app` / `MilesPro` per D-T01/D-T02, enforce `targetSdk=35` per MOBILE-02, generate native icons + splash via the banana skill + @capacitor/assets, and install the Capacitor plugins downstream waves consume (App, Push Notifications, Assets).

Purpose: The current `capacitor.config.ts` is wired for Lovable's dev preview server (`appId: 'app.lovable.e39f4ef4...'`, `server.url: 'https://...lovableproject.com'`, `cleartext: true`). All three values are incompatible with Path C distribution — Universal Links require domain ownership matching the bundle ID, and Apple Review rejects cleartext HTTP. This plan is the single chokepoint where iOS + Android directories materialize. Every subsequent native-touching plan (03-02, 03-03, 03-04, 03-05, 03-06, 03-07) assumes these directories exist and are pinned to the production identity.

<scratchpad>
**Why autonomous: false:** Three sub-steps need either a macOS host (cap add ios) or human interaction with banana skill (icon iteration). The plan is wrapped autonomous=false but most tasks (config file edits, plugin installs) are fully autonomous; only the cap-add-ios + banana iteration steps may pause.

**Why this is plan 03-01 not later:** Every other Phase 3 plan touches files inside `android/` or `ios/`. Without `cap add` running first, those directories do not exist, and pre-write checks in those plans would fail. Front-loading this is structural, not aesthetic.

**Why banana skill is here not 03-04 push or 03-05 client push:** Icon generation is identity work, not feature work. Lumping it with push would (a) bloat 03-04, (b) couple two unrelated concerns. Separate concerns = parallel-friendly waves.

**Server URL removal is the biggest single risk:** `capacitor.config.ts` currently points at `server.url: 'https://e39f4ef4-...lovableproject.com'` — removing this means the WebView no longer loads from Lovable's dev preview. The first `npx cap sync` after this change ships `dist/` as bundled assets. The dev workflow (npm run dev → Capacitor live reload) becomes unavailable for native testing UNTIL we restore `server.url` in development branches. Plan task 1 captures this trade-off.

**targetSdk=35:** Android variables.gradle is the single source. Some templates put targetSdkVersion in build.gradle directly; this project uses the variables.gradle indirection (per `android/app/build.gradle:8-9` references `rootProject.ext.targetSdkVersion`). Plan task 3 bumps variables.gradle.
</scratchpad>
